### List C: Anywhere Code or Docs Call a Metric Misleading, Biased, or Conditionally Invalid
These are explicit criticisms, warnings, and limitations documented across the codebase:

1. **`iqm` on near-binary reward distributions (`eval.py:65-78, 98-99`, `KNOWN-ISSUES.md:3-63`, `RESULTS.md:13-18`, `SESSION-REPORT.md:310-316`)**:
   - *Criticism*: `eval.py`'s `iqm` trims returns from a **single run** rather than across (task, run) pairs using stratified bootstrapping (as defined by Agarwal et al., 2021). On near-binary reward games (CoinRun easy mode, where returns are ~0.0 or ~10.0), this creates a severe step-function artifact at 75% success rate:
     - When success rate < 75%, both 25th and 75th percentiles span [0, 10], retaining all values and making `iqm == mean`.
     - When success rate >= 75%, the 25th percentile lands on 10.0, trimming all failures and snapping `iqm` to 10.0.
   - *Impact*: In the initial single-seed run, SAR had 8/32 failures (25% failures, 75% success), causing its held-out IQM to snap to 10.0 and creating a false appearance of zero generalization gap (10.0 -> 10.0), whereas its true mean return was 7.50 +/- 0.78.
2. **`sem` over n=32 evaluation episodes (`KNOWN-ISSUES.md:25-31`, `SESSION-REPORT.md:317-319`, `_SECOND-OPINION-REPORT.md:121-124`)**:
   - *Criticism*: Re-derivation proves that single-run episode `sem` on CoinRun matches the theoretical binomial standard error $10 \cdot \sqrt{p(1-p)/n} \cdot \sqrt{n/(n-1)}$ exactly.
   - *Impact*: It reflects pure Bernoulli sampling noise from evaluating 32 episodes, NOT algorithmic stability, policy robustness, or cross-seed replicability.
3. **Single-seed evaluation / Point estimates (`RESULTS.md:8-11, 44-47, 78-98`, `PROTOCOL.md:26-27, 95-101`, `SESSION-REPORT.md:77-92, 331-339`)**:
   - *Criticism*: Single-seed comparisons are completely uninformative and statistically invalid. Within-algorithm seed-to-seed standard deviation (0.6-1.2 points) is larger than the gaps between algorithms.
   - *Impact*: The single-seed headline finding ("SAR outperforms all baselines on generalization") was completely overturned when moving to 3 and 5 seeds (where vanilla PPO achieved 7.06 vs SAR's 6.78 and LatentAug's 6.81, with all pairwise differences non-significant at p > 0.30). Pooling episodes within a single seed as independent samples in a t-test is invalid because all episodes share a single trained policy.
4. **`eval/convention` / Overlapping level evaluation (`PROTOCOL.md:21-25, 41-43`, `README.md:20-25`, `eval.py:10-13, 170-171`)**:
   - *Criticism*: Running evaluation with `start_level=0, num_levels=0` samples from the unrestricted level set `[0, INT32_MAX)`, which contains the training levels `[0, 200)`.
   - *Impact*: Calling `eval/convention` a "held-out generalization measurement" is false and misleading because training levels are present in the evaluation distribution.
5. **Raw returns averaged across different Procgen games (`PROTOCOL.md §7:102-104`, `eval.py:190`)**:
   - *Criticism*: Procgen games have vastly different reward scales (e.g. CoinRun max 10, Chaser max 142, BossFight max 100+).
   - *Impact*: Averaging raw returns across games silently ruins aggregate metrics; Procgen-normalized scoring relative to random and human baselines is mandatory for multi-game benchmarks.
6. **`z_style_mu` standard deviation & Style-Swap MSE under over-regularized $eta_{	ext{KL}}$ (`KNOWN-ISSUES.md:64-106`, `SESSION-REPORT.md:208-253`, `viz_latent_aug.py:3-5, 81-83, 110`)**:
   - *Criticism*: When $eta_{	ext{KL}} = 0.01$ (435x too large), the style encoder posterior collapsed to standard prior N(0, I) (`z_style_mu std = 0.0003`, `style sigma = 1.0001`), and style-swap MSE collapsed to 0.00000.
   - *Impact*: The decoder learned to ignore the style code completely, turning data augmentation into an identity no-op and rendering any claim about generative augmentation invalid.
7. **Uncalibrated policy-KL from restored generator variance (`KNOWN-ISSUES.md:91-102, 227-229`, `calibrate_shadow_env.py:158-161`)**:
   - *Criticism*: After fixing $eta_{	ext{KL}}$ to restore style variance (`std = 0.1497`), the resulting decoded augmentations produced policy KL divergences of 0.1767-0.2199, far exceeding the real background swap reference bar (0.1322).
   - *Impact*: Proves that high latent variance is not sufficient; an uncalibrated generative augmentation corrupts foreground semantics, invalidating the assumption that generative style augmentation matches physical environment background variation.
8. **macOS Free RAM (`free_mb()`) in process watchdogs (`SESSION-REPORT.md:144-147`, `_SESSION-LOG.md:128-137`)**:
   - *Criticism*: On macOS, `vm_stat` free pages are kept near zero intentionally by the kernel disk cache.
   - *Impact*: Measuring free RAM as an indicator of memory exhaustion is a structurally invalid signal on macOS, causing watchdog scripts to falsely terminate training runs. Swap growth (`sysctl vm.swapusage`) must be used instead.
9. **`info["episode"]["r"]` evaluation return readout (`eval.py:33-38`)**:
   - *Criticism*: In standard gym environments, `info["episode"]["r"]` is populated only if `VecMonitor` wrapper is in the chain.
   - *Impact*: `PROTOCOL.md §4` default wrapper chain stops at `VecNormalize`, so relying on `info["episode"]["r"]` silently yielded zero completed episodes forever against real Procgen environments. `eval.py` must track cumulative rewards manually.
10. **`code_version` in declaration blocks (`eval.py:156-162`, `_SECOND-OPINION-REPORT.md:176-181`, `RESULTS.md:171-175`)**:
    - *Criticism*: `eval.py` extracts code version via `git rev-parse --short HEAD`, which reads the last committed git commit hash and ignores working-tree dirtiness.
    - *Impact*: Evaluation declaration blocks reported identical git commit SHAs for runs that actually executed on different (uncommitted) code states.
