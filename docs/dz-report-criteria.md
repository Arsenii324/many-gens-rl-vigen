# Критерии отчёта супервизору (DZ) — чек-лист для вычитки

Составлено до написания текста, чтобы вычитка была проверкой, а не самооправданием.

## A. Письменный отчёт (10–15 минут чтения, ~2000–2600 слов)

| # | Критерий | Как проверяется (объективно) |
|---|---|---|
| A1 | **Главный факт статуса — в первом абзаце.** Если результатов нет, это первое предложение, а не вывод на третьей странице. | Найти в тексте «ноль прогонов»; проверить, что он выше любого описания достижений |
| A2 | **Каждое число прослеживается до артефакта.** Ни одной цифры «по памяти». | Для каждого числа в тексте — файл, лог или команда рядом или в приложении |
| A3 | **Три категории разделены явно:** установлено / решено нами / открыто и требует DZ. | Каждый раздел помечен; ни один пункт не находится в двух категориях |
| A4 | **Решения для супервизора вынесены отдельно, с ценой вопроса.** Не «что вы думаете», а «вариант A стоит X, вариант B стоит Y, рекомендация — A». | Отдельный раздел; в каждом пункте есть рекомендация и последствие |
| A5 | **Приоритет, а не хронология.** Важное первым; «что я делал по дням» отсутствует. | Проверить, что порядок разделов — по важности, нет слова «затем» как структуры |
| A6 | **Собственные ошибки названы.** Отчёт, где ошибались только внешние источники, недостоверен. | Найти минимум один пункт «я ошибся / мы ошиблись», с исправлением |
| A7 | **Негативные и отсутствующие результаты не спрятаны** (требование навыка: scope constraints, не material to hide). | Проверить, что «нет прогонов», «Lift недобирает бюджет», «нет continuous-референса для двух методов» присутствуют явно |
| A8 | **Термины единообразны и расшифрованы при первом употреблении.** | Проверить: кадры/шаги агента, мутационное тестирование, протокол-хеш, общий энкодер |
| A9 | **Никаких невыполнимых обещаний.** Оценки сроков либо с диапазоном и допущениями, либо отсутствуют. | Найти все обещания; у каждого — допущение |
| A10 | **Заканчивается конкретным следующим шагом и явным запросом.** | Последний раздел содержит список действий и список вопросов |
| A11 | **Объём соответствует времени.** 2000–2600 слов. | Подсчёт слов |

## B. Устная версия (10–15 минут речи, ~1400–1900 слов при ~130 сл/мин)

| # | Критерий | Как проверяется |
|---|---|---|
| B1 | **Устный синтаксис.** Короткие предложения, без вложенных придаточных и скобок. | Средняя длина предложения ≤ 20 слов; нет предложений > 35 слов; скобок нет |
| B2 | **Числа округлены и произносимы.** Слушатель не может перечитать. | Нет `8.0e-5` в тексте для произнесения — только «восемь на десять в минус пятой»; нет `file.py:172` |
| B3 | **Явная навигация.** Слушатель всегда знает, где мы. | Есть «три вещи», «первое / второе / третье», переходы между блоками |
| B4 | **Каждый блок начинается с вывода, затем обоснование.** | Первая фраза блока — утверждение, не подводка |
| B5 | **Явные точки остановки для решения DZ.** | Минимум 2 фразы вида «здесь нужно ваше решение» |
| B6 | **Тон: без оправданий и без хвастовства.** | Нет «к сожалению», «увы», «огромная работа», «очень много» |
| B7 | **Ссылки на документы вместо номеров строк.** | Все `file:line` заменены на «в документе X» |
| B8 | **Хронометраж размечен.** | Блоки с отметками времени, сумма 10–15 минут |
| B9 | **Тот же фактический состав, что и в письменном.** Устная версия не «мягче». | Сверить: ноль прогонов, собственная ошибка, открытые решения — присутствуют |

## C. Взято из внешних источников (Липтон, Хьюз, Кнут)

Аудитория здесь — **супервизор и участники команды**: они и читают, и слушают, знают проект и
читают тот же код. Это меняет калибровку: специальный термин у такой аудитории **яснее**
описательного оборота, поэтому «сид» лучше, чем «запуск с разным случайным зерном», а
«мутационное тестирование» и «дифф» не требуют замены.

| источник | правило | как применено |
|---|---|---|
| Липтон | Не дразнить читателя: главный результат — сразу | «Ноль прогонов» — первая строка обоих отчётов |
| Липтон | Выбросить усилители («очень», «полностью») | 0 в обоих текстах; проверяется по **полному** тексту, включая таблицы |
| Липтон | Не приписывать намерений вещам («алгоритм пытается») | 0 |
| Липтон | Заложники судьбы: не утверждать того, что можно оспорить | «разброс ±20 п.п.» вместо «свип стал хуже» |
| Липтон | Мнение маркируется как мнение | «Рекомендую», а не «правильно будет» |
| Хьюз | Начинать с презентации — она заставляет выделить главное | Устная версия писалась не пересказом, а отдельно |
| Хьюз | **NEVER RE-USE TEXT** | 0 дословных совпадений предложений между версиями из 112 |
| Хьюз / Питон-Джонс | Внимание убывает: заголовок читают все, детали — единицы | Блок «Что требуется от вас» поднят в начало письменного отчёта |
| Уильямс (через Хьюза) | Кто что сделал: действующие лица — подлежащие | Проверено вручную |
| Уильямс | Старое в начале предложения, новое в конце (позиция ударения) | Проверено вручную по абзацам |
| Кнут #14 | Одно понятие — один термин | «хеш протокола» (как `protocol_hash` в коде) везде; «отпечаток» удалён |
| Кнут #18 | Малое число прилагательным — словом | «в пять раз», не «в 5 раз» |
| Кнут #6 | «мы» — про проект, «я» — там, где нужна личная ответственность | «я» о собственной ошибке и триаже, «мы» о решениях проекта |
| Кнут #26 | Не нанизывать существительные / не жаргонить без нужды | Цепочек родительного падежа 3+ — 0 |
| Кнут #2 | Не начинать предложение с символа | 0 в устном |

**Не применялось и почему:** правила про формулы, теоремы, библиографию, число ссылок, рисунки и
подписи (Липтон, Кнут ##1–5, 15–17, 19, 23) — в статусном отчёте нет ни формул, ни теорем, ни
списка литературы. Правило Кнута #13 («текст должен читаться, если формулы заменить на „бла“»)
применимо и выполняется: имена вроде `aux_lr` можно заменить на «параметр», и фразы остаются
связными.
